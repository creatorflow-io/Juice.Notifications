# Deferred findings

Review findings that are not correctness bugs: efficiency, cleanup and operability ideas. They don't block a milestone. Larger efficiency work is
picked up in the milestone where it can be measured (M8: history, operations and host), not fixed speculatively.

| 1 | M1 review, round 3 | A lost race that the API answers (`application_exists`, a fresh 200, `tenant_in_use` or `concurrent_change`) still logs at Error level twice: EF Core's SaveChanges failure and Juice `TransactionBehavior`'s "ERROR Handling transaction". Log-based alerts would fire on normal traffic. Options: lower EF's `Microsoft.EntityFrameworkCore.Update` category for conflicts, and raise with Juice whether `TransactionBehavior` should log conflicts below Error. | M8 (operations): with the metrics and alert rules |
| 2 | M1 review, confirmations 3 and 4 | **Juice task: commit failures in `UnitOfWork`.** Juice 10.12.0's `UnitOfWork.CommitTransactionAsync` rolls back a transaction Npgsql already completed when `COMMIT` fails, and the rollback's "has completed" error replaces the real one, so a commit-time conflict is not recognized (500). A first fix is in the Juice working tree, **uncommitted** (`core/src/Juice.EF/UnitOfWork.cs`, `UnitOfWorkCommitTest`, changelog). Its review found it must not ship as is: (1) `DbContextBase.CommitTransactionAsync`'s `finally` reload can still replace the error; (2) **with `EnableRetryOnFailure`, a transient commit error now reaches the execution strategy, which re-runs `ResilientTransaction` after SaveChanges accepted the changes, commits an empty transaction and reports success: writes lost**; (3) only `InvalidOperationException` from the rollback is swallowed; (4) a failing `OnTransactionCommittedAsync` still fails the command, clears post-commit actions and skips the commit announcement although the data is committed; (5) the "no longer active" test assertion is vacuous. Needs a decision on how commit failures interact with Juice's retry strategy first. Phase 1 has no commit-time conflicts (no deferred constraints, read committed) and stays on 10.12.0. | Its own Juice task; bump `Juice.*` once released, before any deferred constraint or stricter isolation is used |

| 6 | M2 review, round 2 | **Hardening:** JsonSchema.Net matches each schema `pattern` with its own fixed 5 s timeout, and offers no hook to change it, so a pattern that backtracks without end holds a request thread up to 5 s per string it checks before the data is refused (422).
